= Forced Let's Encrypt Renewal Validation
:toc:

== Purpose

This checkpoint records one controlled end-to-end production certificate renewal validation for:

----
atreides.lan.rirl.dev
----

The objective was to prove the full rotation path:

----
new certificate issued
-> installed
-> nginx serving that exact certificate
-> LAN clients trust it
-> canary succeeds
----

== Controlled production renewal

The normal renewal timer was intentionally paused before the experiment.

The repository-approved renewal script was extended with an explicit:

----
--force-renewal
----

option.

The script continued to use the approved operational path:

----
renew-certificates.bash
-> Docker
-> certbot/dns-cloudflare:v5.7.0
-> certbot renew --non-interactive --force-renewal
----

The forced production renewal completed successfully.

No second forced renewal was performed.

== nginx rotation behavior

Immediately after successful renewal, nginx continued to serve the old certificate.

The on-disk certificate fingerprint was:

----
B6:05:E4:05:1F:35:96:46:46:1C:CB:1B:30:E9:67:7E:BC:A4:72:8B:82:71:E8:90:A7:D1:D6:56:85:0F:01:D8
----

The certificate presented by nginx was still:

----
87:93:38:67:7F:36:EB:B3:C0:1D:89:94:ED:3B:4A:ED:D2:CB:93:22:74:5B:4D:91:5D:F6:92:EE:2F:CB:37:8F
----

Therefore nginx did not automatically load the renewed certificate.

The nginx configuration was validated successfully with:

----

----

nginx was then reloaded in place with:

----
nginx -s reload
----

After reload, nginx presented the exact newly issued certificate:

----

== Result

PASS.

The controlled production certificate rotation path was successfully demonstrated:

----
Let's Encrypt production issuance
-> Certbot installation
-> Certbot live symlink rotation
-> nginx reload required
-> nginx presents exact new certificate
-> atreides trusts certificate
-> harkonnen trusts certificate
-> TLS canary returns ok
----

== Operational finding

Certificate renewal alone is insufficient to complete service rotation.

The operational renewal workflow must include an explicit, validated nginx reload after successful certificate renewal.

A future implementation should ensure that reload occurs only after successful renewal and should preserve failure visibility if reload validation fails.
